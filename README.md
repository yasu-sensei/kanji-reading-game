# 漢字読み方ゲーム

提供された `kanji_reading_game_prototype_v04-2.html` を土台に、400問CSVと完成済みガチャ・図鑑を統合したChromebook向けゲームです。

## 5つの画面

1. **登録** — `index.html` で1〜4組・1〜35番を選ぶ（添付試作版の範囲を維持）。
2. **準備** — CSV初出順の80字から学習済み漢字を選び、宿題／練習を開始。
3. **三択** — CSVの正答・誤答をそのまま使用。10問、即時正誤表示、最大2周の復習。
4. **ガチャ** — `gacha.html`。学習で得た星1個で1回。完成済みの回転・排出・開封演出を使用。
5. **図鑑** — `collection.html`。児童別のカードを表示。通常・金・虹の33×3＝99枚。3枚獲得済みは抽選対象外。

## 起動

追加の依存パッケージ・ビルドは不要です。リポジトリのルートで実行します。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザーで配信先の `/` を開きます。主にChromebookのタッチ操作・横持ち／縦持ちを想定しています。

## 学習と保存

- 宿題は同じ児童について日本時間で1日1回。初回回答10問正解で星2個、5〜9問で1個、0〜4問で0個。
- 練習は完了5セットで星1個。途中でやめたセットは数えません。
- **10問目の回答直後**、正誤表示中に記録・星・宿題完了を一括保存。セット固有IDで再保存の二重加算を防ぎます。
- 保存失敗時は変更を確定せず通知し、結果画面で同じセットの保存を再試行できます。復習では星・セット数を追加しません。
- 漢字1字の場合もその5問を含めて10問を出します。
- 学習の抽出は添付版の「未出題から最大5問・誤答履歴から最大3問・残りを補充」を暫定的に維持。正式な習熟度計算・出題比率は未確定です。
- 抽選は3枚未満の種類から等確率の暫定方式。シークレットの別条件・本番排出率は未確定です。
- `kanji-reading-prototype-v1` に学級・番号ごとの選択・履歴・星・`cardCounts`を保存。添付版と同じ保存キーで、既存のプロフィールを維持します。ガチャのおためし用の星・カードは学習側へ移しません。
- 対応ブラウザーではWeb Locksで同じ保存キーの更新を直列化。ガチャの消費とカード獲得も一括保存し、演出中の連打を防ぎます。
- **端末内保存です。** 同じ学級・番号でも端末／ブラウザーが違えば別の記録です。サーバー同期・教師集計・パスワードによる本人認証は未実装。ブラウザーの保存データ削除によって記録も失われます。

## 問題・画像

- `data/kanji_400_final.csv`：提供原本とバイト単位で同一。問題番号・語彙・正答・誤答・確認状況は変更しません。
- `images/`：提供33枚。正式名称に修正・軽量化済み。金・虹の効果はCSSで重ね、今回画像自体は変更していません。
- 個人の学級・番号・学習履歴はブラウザー内に保存し、リポジトリには書き出しません。
- 仕様・変更履歴は `docs/SPEC.md`、開発ルールは `AGENTS.md`。

## 動作確認

Playwright・Chromium導入済みの開発環境で、HTTPサーバー起動後に実行します。

```sh
python3 tests/validate_questions.py
node tests/integration.cjs
node tests/learning-save.cjs
node tests/rewards.cjs
node tests/gacha-animation.cjs
```

過去の単独おためし画面は `preparation.html`・`quiz.html`、ガチャ／図鑑の単独デモは `?demo=1` に残しています。通常の登録→準備の導線では使用しません。これらの互換性確認は `node tests/preparation.cjs` と `node tests/quiz.cjs` で行います。

## 画像・CSVを内蔵する単一HTML

```sh
python3 scripts/build-preview.py /tmp/kanji-preview
```

出力先の `kanji-preview.html` とZIPに登録・準備・三択・ガチャ・図鑑をまとめます。通常のファイル構成と同じ保存キーを使いますが、保存先はブラウザーのオリジンごとに分かれます。
